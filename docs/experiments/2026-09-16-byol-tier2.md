# BYOL Tier 2 review and experiment

This experiment executes the protocol already declared in the BYOL card, §6.
It does not change the fixture, architecture, optimiser, thresholds or seeds
after observing results. It tests a local tabular adaptation, not ImageNet
reproduction or causal identification.

## Changes

- Generalise the existing paired study to accept explicit row counts, training
  budgets, warmup, marginal ramp and diagnostic batch count. Tier 1 defaults
  remain unchanged. At Tier 2 the full arm matches the recipe's schedules.
- Register BYOL in the benchmark registry and add its nightly pytest adapter.
  Bind all nine reproduction YAML fields by value.
- Add within-seed EMA, pretraining-cost and predictor contrasts, treatment NLL
  and original-scale treatment-effect RMSE. Retain all arm ranks, norms,
  spreads, BN diagnostics, residuals and target-online lag.
- Check that diagnostic evaluation preserves target state as well as online
  state, and require diagnostic batches to cover the held-out population.
- Add strict `<` support to the shared metric reporter. The card requires
  `mean + SE < 0.05`; the existing inclusive upper-bound helper would accept
  equality. Existing recipes' inclusive rules remain unchanged.
- Update the original Tier 0 lifecycle assertion, which still required an
  `implemented` card and an empty ledger. CI exposed this stale assertion
  after the result was recorded. It now requires a measured lifecycle status
  and a nonempty EMA result; the independent replay checks that status against
  the saved evidence.

The study already checked losses and gradients at every step. That code is
retained; an initial review suspicion that it checked only final values was
incorrect.

## Execution and provenance

Run from local committed source snapshot `49df876e8ad9cfc40f69b522f2dead8a468a325c`:

```bash
uv run --no-sync python -m xty2.evaluation.runner \
  --recipe byol --workers 5 \
  --output docs/experiments/results/byol-tier2 --write-ledger
```

Ten bases are `620000 + 100*i`, for `i=0..9`. Each replicate runs all four
arms, using 1024 training rows, 2048 held-out rows, 40 observed treatments,
batch 128, 1000 pretraining steps where applicable and 3000 downstream steps.
Warmup is 10 steps and the downstream marginal ramp is 1000 steps. Diagnostic
views use 16 fixed batch pairs; clean encoder rank uses all held-out rows
before fine-tuning. No early stopping or checkpoint selection is used.

Actual initial tensors, execution streams, view draws, masks, fitted scales,
teacher updates and stage transfers are checked during fitting. Missing
treatment payloads are replaced with dummy class zero before model execution.
All seeds are retained. Differences are computed within seed before sample
standard errors, with `ddof=1`, are calculated across ten replicates.

The [environment manifest](results/byol-tier2/environment.json) records the
source tree, Python, Torch and NumPy versions, and SHA-256 hashes of every
tracked implementation file. The compiled recipe plan is unchanged by this
patch and remains in the PR description.

The source snapshot is preserved as [a patch](results/byol-tier2/source.patch)
against `ebbbf8a49b18debee7fe640d7da97e2dfd623ac0` and its
[exact commit object](results/byol-tier2/source-commit.txt), so the runner,
registry and completed result can land together in one branch commit.
Applying the patch to that parent with `git apply --index --unidiff-zero` and running
`git write-tree` reconstructs the manifest's source tree. The commit object
hashes to the recorded source SHA with `git hash-object -t commit`.
Both reconstruction checks were executed successfully.
