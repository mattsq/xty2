# Proposal: adaptive self-play tasks for tabular SSL

**Status:** research proposal, not a reviewed recipe or implementation contract  
**Source:** Cowsik et al., [*Self-Play Pretraining with Zero Data*](https://arxiv.org/abs/2609.30063v1), especially §2.2 and Appendix F  
**Question:** Can a learner-adaptive distribution over tabular self-supervised tasks improve downstream transfer over a fixed distribution over the *same* tasks at equal total compute?

## 1. Thesis and scope

The source paper jointly trains a generator of executable programs and a learner on their outputs. Its distinctive contribution for this project is a reward for programs that exercise directions in which the learner has made sustained progress, rather than programs with high current loss. It compares the adaptive generator with fixed sampling over the same program language; its reward ablations show that the long lookback, AdamW preconditioning, and program-specific reward carry signal. These are results for byte-sequence prediction, not evidence that the mechanism already works on tables.

The proposed first test keeps real, unlabeled tabular rows and lets a controller select *which admissible self-supervised problem to pose*. The follow-up test replaces real rows with a typed generator of synthetic tables. These are separate claims:

1. **Real-`X` SSL:** adapt a distribution over corruption and prediction tasks using only the training split's covariates.
2. **Synthetic-prior learning:** adapt a distribution over table-generating programs and measure transfer to unseen tasks.

Neither claim implies causal identification, and a gain in a masked-feature objective alone would not establish useful transfer.

## 2. Source mechanism and proposed mapping

For candidate task `q` at learner step `e`, use a separately sampled training batch to compute

```text
delta_e = theta_floor(e/2) - theta_e
P_e     = lr_e / (sqrt(vhat_e) + eps)
r(q)    = abs(<grad_theta L_q(theta_e), P_e * delta_e>)
```

Here `vhat_e` is the learner AdamW second-moment estimate, and the dot product spans the parameters trained by the *common* SSL objective (at least the encoder and prediction head). This is the paper's Eq. 2 mapped from generated byte strings to tabular tasks. Keep its absolute value for the primary experiment; measure the sign and include a signed-reward ablation because absolute value can also reward opposing directions. Do not silently replace the historical checkpoint with `theta_(e-1)` or omit preconditioning. During a short warm-up, sample uniformly until the lookback checkpoint and optimizer moments are informative.

`q` is a declarative, seeded task specification, not a learned label. The first controller can be a finite softmax bandit with a probability floor and temperature, updated from standardized rewards. This substitutes a simpler search method for the paper's transformer generator, policy-gradient update, mutation archive, and replay. Record that departure explicitly. It tests adaptive selection using the paper's reward, **not** a reproduction of the complete source method.

Score several candidates on fresh covariate batches at a specified interval, then draw one or a small mixture for learner training. Keep scoring and learner-update draws separate and account for *all* candidate forward/backward or JVP work in the compute budget. Log candidate probabilities and costs. A fixed uniform distribution, using the same candidate set, batches, number of learner updates, and total scored-gradient budget, is the crucial control. The comparator can spend the same budget on unused scores so wall time and gradient calls are matched; also report a practical comparison without that artificial overhead.

## 3. First experiment: conditional feature prediction

Use one encoder, one masked-feature prediction head, and one loss family across all candidate tasks. A task chooses a target column or small target subset, visible columns, and a corruption policy. Predict original held-out values from a view in which target values cannot reach the encoder. Continuous targets use a fixed standardized regression loss; categoricals use cross-entropy. For the initial experiment, use an all-continuous fixture or predeclare a fixed normalization across target types so reward magnitudes are comparable. Sample targets and score candidates with matched row count and a fixed target-loss scale.

Candidate configurations (start with approximately 24–40) can vary:

| Axis | Initial choices | Constraint |
|---|---|---|
| Target | one feature; a related pair; a random subset | target values withheld from every model input |
| Context | near-full; sparse; feature groups | at least one visible and one hidden feature |
| Context corruption | schema-valid mask; bounded jitter; marginal replacement | never mutate immutable, derived, or out-of-bounds features illegally |
| Difficulty | low/medium/high rates | tasks must remain executable and nondegenerate |

The candidate space must be fixed before evaluating outcomes. Use only the training population to fit marginal replacements, encodings, bounds, and scaling. No treatment, outcome, observation mask, potential outcome, or evaluation metric enters the task generator or reward. For synthetic fixtures with known feature relationships, the test split and downstream evaluation labels stay inaccessible to controller selection.

A secondary experiment can allow view-pair objectives such as SCARF, BYOL, or VICReg. Those require separate loss-scale calibration and valid-view policies: a controller that simply prefers the largest raw gradient, or picks a transformation that destroys the target, has not found a useful curriculum. The [VICReg valid-view proposal](vicreg-valid-views.md) is a concrete warning that tabular transformations need a semantic contract. Mixing named SSL algorithms should follow a clean single-objective result rather than enter the first comparison.

## 4. Evaluation and controls

Use a train/tuning/test split established before controller development. Pretrain on `X` from the training split only. Freeze the encoder, then train the *same* small supervised head with the *same* restricted label budget and seeds for every arm. The primary endpoint should be predeclared on a selected existing fixture, for example held-out outcome NLL at a fixed small labeled budget. Secondary endpoints: treatment NLL, representation spread/collapse, masked-feature prediction on unseen rows, and PEHE/ATE error only on synthetic DGPs where counterfactual ground truth exists. For causal metrics, use the repository's ordinary split and leakage guardrails; do not treat the learned representation as a guarantee of unconfoundedness.

Predeclare a small study across multiple fixtures: one with redundant/dependent columns, one with interactions and mixed noise, one with weakly informative or independent columns, and, if available, one real dataset. Include column-order permutations, irrelevant columns, missingness, and schema-valid categorical variants as later robustness probes. The independent-column fixture is especially useful: a generator may optimize reward without finding transferable dependency structure.

Minimum paired arms, sharing initial weights, row order, augmentation RNG policy, label subsets, optimizer, and learner-update budget:

1. Fixed uniform task sampling over the identical candidate set.
2. Fixed, tuned masked-feature task policy (a credible strong baseline).
3. Adaptive long-horizon, preconditioned alignment (the proposed arm).
4. Adaptive current loss or one-step/loss-delta reward (difficulty/progress control).
5. Adaptive shuffled reward across candidates (selection-signal control).
6. Signed and no-preconditioner reward ablations, run after the primary comparison or within a predeclared ablation budget.

Report every seed, paired differences with uncertainty, best and final checkpoints, score-computation cost, candidate frequencies over time, reward distribution, gradient norms, and instances of reward–transfer disagreement. Use one seed for debugging only; set acceptance thresholds from the study design rather than from a favorable pilot. A useful positive result is a reproducible paired gain over *both* fixed controls on the predeclared downstream endpoint at equal compute, without leakage, collapse, or reliance on a single candidate. Failure on transfer despite improved proxy reward is a substantive negative result.

## 5. Implementation boundary in xty2

Keep the initial controller as an **experiment driver around compiled runs**, not as a new recipe or sampler contract. Today `ViewSpec` describes schema-aware functional views and `Stage` chooses a fixed sampler and objective schedule; `DESIGN.md` §7.3 explicitly defers stateful sampling. A model-dependent task controller cannot honestly be smuggled into a static `ViewSpec`, `UniformSampler`, or a recipe function containing procedural logic.

Suggested sequence:

1. Draft a fixed-task masked-feature recipe card, using `docs/recipes/_TEMPLATE.md`, and review it before implementing any new recipe mechanic. Reuse existing reconstruction ports/views where possible. Reviewed as [`recipes/vime.md`](../recipes/vime.md) (VIME-self, Yoon et al. 2020), status `implemented`.
2. Pilot the controller in a bounded experiment that selects among precompiled fixed task configurations or drives explicitly supplied batches. If the executor cannot interleave selection and model updates without breaking its provenance guarantees, record that limit and keep the pilot external; do not represent the pilot as a normal compiled recipe.
3. If transfer justifies integration, propose a controller/executor contract under `DESIGN.md` §11.2: declared candidate space; train-only data access; RNG and split provenance; checkpoint/optimizer/lookback state; scoring budget; plan digest; logs; restart semantics. Add an architectural primitive only with a reviewed consumer and invariants.
4. Separate the controller's research result from reproduction status of existing SCARF/BYOL/VICReg cards. A dynamically mixed training run is a new method with its own card and evidence.

Useful invariants for a later implementation: zero target leakage under each view; no access to evaluation rows or labels; deterministic candidate execution under a seed; optimizer state and historical checkpoint restored exactly on resume; reward-gradient probes do not update learner weights or optimizer moments; all candidate costs included; train-only statistics carry their row IDs. A Tier 1 fit can establish wiring, but a downstream Tier 2 paired study decides the research claim.

## 6. Second experiment: adaptive synthetic table programs

Only if the real-`X` test is informative, define a bounded typed DSL for tabular data-generating processes:

```text
latent distributions -> continuous/categorical columns
columns -> thresholds, interactions, piecewise functions, monotone transforms
noise -> independent/correlated/heteroscedastic
masking -> declared missingness process
optional y -> known synthetic downstream task, hidden from controller reward
```

Each executable program generates a table and a set of masked-prediction problems. Sample program lengths, row counts, feature counts, column order, and irrelevant features; reject invalid programs deterministically and cap execution cost. Compare a fixed prior and an adaptive distribution over **the identical DSL**, with equal generated rows, learner architecture, updates, and total compute. Evaluate zero-shot or fixed-budget adaptation on held-out real tables and held-out DGP families, with tuning separate from test. This tests whether a learned synthetic prior transfers; it is not the same experiment as adapting augmentations on a given real table.

Potential intermediate variants: generate symbolic columns from real training `X`; reward synthetic tasks against a progress direction measured on real training `X`; or learn a controller over already implemented SSL operators. Each changes the data access, reward interpretation, or objective scale and should have its own comparison rather than be bundled into the first result.

## 7. Decisions to make before a recipe card or benchmark

- Choose the primary fixture and label budget, and register the primary downstream metric and seed stream.
- Define the exact finite task set, target-loss normalization, and schema policy.
- Set the number of candidate probes per round, update frequency, warm-up, probability floor, and full compute accounting.
- Decide the external experiment boundary after checking whether existing execution APIs can resume between controller decisions without losing optimizer/checkpoint state.
- Specify a genuine fixed-policy tuning budget and a downstream test split that the controller and hyperparameter search never see.

**Go/no-go:** advance to a framework integration proposal only if the adaptive arm improves paired downstream transfer at matched compute and the reward/task trace rules out leakage, scale selection, and representation collapse. Otherwise retain the experiment and its failure mode as evidence about the proposed reward on tabular objectives.
